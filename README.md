## 📑 Lab Summaries & Deliverables

### [Lab 1: Requirements Engineering & UML Use-Case Modelling](./Lab/Lab%201)
- **Problem Statement:** Problem Statement #16 – Remote Patient Vitals Alert & Monitoring App
- **Key Concepts:** Functional Requirements (FR), Non-Functional Requirements (NFR), Actor Identification, UML Use-Case Diagrams.
- **Deliverables:**
  - Complete Requirements Table (FR-001 to FR-005, NFR-001 & NFR-002 with ID, Type, Description, Priority, Acceptance Criteria, and Rationale).
  - UML Use-Case Diagram with `«include»` and `«extend»` relationships.
  - Detailed Use-Case Flow Specification document.

---

### [Lab 2: Agile Backlog Creation & Sprint Simulation in Jira](./Lab/Lab%202)
- **Objective:** Convert requirements into Agile backlog items, simulate a sprint cycle, and monitor progress using Jira.
- **Key Concepts:** Epics, User Stories, Fibonacci Story Point Estimation, Planning Poker, Scrum Board, Burndown Charts.
- **Deliverables:**
  - Backlog view with Epics, User Stories, and Story Points assigned.
  - Active Sprint Board view (`To Do` → `In Progress` → `Done`).
  - Sprint Burndown Chart analysis report.
  - Reflection questions addressing estimation accuracy, prioritization, and team velocity.

---

### [Lab 3: Component Modelling & Architectural Pattern Selection](./Lab/Lab%203)
- **Objective:** Evaluate software architectures, select the optimal style for the scenario, and design UML component models.
- **Key Concepts:** Layered vs. Microservices vs. Client-Server architecture, Ball-and-Socket interface notation.
- **Deliverables:**
  - UML Component Diagram (with at least 5 components and 4 interfaces).
  - Architectural Justification Document detailing rationale, security considerations, and performance benefits.

---

### [Lab 4: VibeCoding](./Lab/Lab%204)
- **Objective:** Leverage LLM-based prompting (ChatGPT/Gemini/Claude) to debug broken code and iteratively add features.
- **Key Concepts:** Prompt engineering, iterative software development, automated test-driven fixes.
- **Deliverables:**
  - Before and After execution demo videos.
  - Refactored and enhanced source code files.
  - Exported prompt conversation history document.

---

### [Lab 5: Static Code Analysis](./Lab/Lab%205)
- **Objective:** Perform static analysis on Python code to identify style violations, logical bugs, and security vulnerabilities.
- **Tools Used:** Pylint, Bandit, Flake8.
- **Deliverables:**
  - Cleaned Python source code with fixed issues.
  - Pre-fix and Post-fix diagnostic reports (`pylint_report.txt`, `bandit_report.txt`, `flake8_report.txt`).
  - Issue log table documenting detected issues, severity, line numbers, and applied fixes.

---

### [Lab 6: Code and Branch Coverage Analysis](./Lab/Lab%206)
- **Objective:** Design comprehensive unit test suites to measure and achieve high statement and branch coverage.
- **Tools Used:** `pytest`, `coverage.py`.
- **Deliverables:**
  - Code coverage test suite (`CodeCoverageTest_*.py`).
  - Branch coverage test suite (`BranchCoverageTest_*.py`).
  - Terminal execution reports and screenshots demonstrating ≥ 90% code and branch coverage.

---

### [Lab 7: Fuzzing for Input Validation Bugs](./Lab/Lab%207)
- **Objective:** Discover unexpected crashes, unhandled edge cases, and security vulnerabilities through property-based fuzz testing.
- **Tools Used:** `Hypothesis`, `pytest`.
- **Deliverables:**
  - Hardened application source script (`processor.py`).
  - Completed Hypothesis test suite (`test_processor.py`).
  - Screenshots capturing failing test runs (bugs identified) and passing test runs (post-fix).
